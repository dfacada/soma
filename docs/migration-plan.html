Migration plan · September 2026

Glimpse on Catalyst

Moving the whole stack off Vercel and Supabase onto Zoho Catalyst: the app, eight edge functions, nine tables, three storage buckets, one cron job, and eight users' encrypted vaults.

repo: dfacada/glimpse app: 8,559-line single HTML users: 8 · entries: 129

Verdict: doable, but it is a re-architecture, not a lift-and-shift. Catalyst has no row-level security and caps HTTP functions at 30 seconds. That forces two changes the current app was built to avoid: every database call has to go through an API layer instead of the browser talking to tables directly, and transcription has to become an async job. Plan for roughly 4 weeks of focused work across six phases, with a spike first to confirm four things the docs don't state.

The end-to-end encryption design is the reason this is survivable: ciphertext and the vault salt move byte-for-byte, so nobody has to re-enter a passphrase or loses an entry.

What runs today

Vercel

  • Static hosting for glimpse-secure.html, the Whisper worker, icons, manifest, walkthrough
  • One rewrite: / → glimpse-secure.html
  • One header: manifest Content-Type
  • Auto-deploy from master
  • Origin glimpse-seven-livid.vercel.app is hard-coded in every function's CORS allowlist and in the Fitbit OAuth app

Supabase

  • Auth: email + password, JWT sessions, refreshSession
  • Postgres: entries, vault_meta, vault_tokens, fitbit_daily, checkins, user_prefs, errors, feedback; RLS on every table, explicit grants
  • Storage: audio, photos, audio-drafts (200 ms chunks streamed during recording)
  • Edge functions (Deno): transcribe-cloud → Groq · analyze-patterns and analyze-entry → Anthropic · fitbit-oauth-exchange, fitbit-sync → Fitbit · admin-stats, am-i-admin, ack-feedback, admin-clear-errors
  • pg_cron: nightly prune of errors older than 30 days

Unaffected: the Whisper worker loads @xenova/transformers from jsdelivr, the Orbit bridge talks to localhost:4747, and the vault key never leaves the browser.

Four things that change the architecture

Verified against the Catalyst docs this week. Each one is a design decision, not a config toggle.

Data Storere-architect

No row-level security

Permissions are per table and per role: select, insert, update, delete. Nothing filters rows by owner. Today the browser calls SB.from('entries') directly and RLS keeps users apart. On Catalyst every read and write must go through a function that checks the caller and adds where user_id = ? itself.

Functionsre-architect

30-second HTTP timeout

Advanced I/O functions hard-stop at 30 s. Groq takes up to 90 s on a 25 MB file, and the pattern analysis call to Claude runs 10 to 25 s. Both become jobs: the client submits, a background function (900 s budget for Cron/Event types) does the work, the client polls.

Data Storereshape

Text columns cap at 10,000 characters

An entry's ciphertext is stored today as a JSON integer array in a Postgres column, often 50 to 200 KB. It cannot live in a Data Store column. Move entry ciphertext to Stratus as a binary object, exactly the format audio already uses, and keep only metadata in the table.

Authreshape

Passwords don't migrate, sessions are Catalyst's

Catalyst issues its own user IDs (numeric) and manages sessions via its web SDK. Supabase password hashes cannot be imported. All eight users get an invite and set a new login password. Their vault passphrase is unchanged, so their data decrypts as before.

Phases

Sequenced so nothing on the live site changes until phase 5. Estimates assume one person working with Claude and a normal amount of console poking.

02–3 days

Spike: prove the four unknowns

  • Create the Catalyst project. Deploy a hello-world Slate site from a branch with no build step and confirm / serves the HTML and .webmanifest gets the right type.
  • Wire embedded email sign-up and sign-in on that page. Confirm an Advanced I/O function can read the caller's user ID and email from the request.
  • Stratus: upload a 25 MB object from the browser via a pre-signed URL with bucket CORS on. Download it the same way. Note the expiry options.
  • Submit a job from the API function that sleeps 60 s, then writes a row. Confirm the timeout budget for whatever job type Catalyst gives you (Job Scheduling if it is available to the account, otherwise an Event function).
  • Export analyze-entry from the Supabase dashboard into supabase/functions/ and commit it.
ExitAll four work, or you have a concrete workaround for the one that doesn't. If pre-signed uploads or the job budget fail, stop and revisit the plan before writing more code.
15–7 days

Backend: the API function, jobs, and cron

  • New folder catalyst/functions/glimpse_api (Express). Routes mirror today's client calls: /entries list/upsert/delete, /vault-meta, /vault-tokens, /prefs, /checkins, /fitbit-daily, /errors, /feedback, /sign (batch pre-signed URLs), /jobs.
  • Every route resolves the caller first and scopes every query by user_id. Admin routes check a Catalyst role.
  • Port the eight Deno functions to Express handlers or job functions. Secrets go in the function's environment variables, with separate dev and production values.
  • Job function glimpse_jobs: transcribe (Groq) and analyze (Anthropic). Writes results to a jobs table the client polls.
  • Cron function glimpse_nightly: prune errors older than 30 days.
  • Data Store tables created from a checked-in schema script; column notes in catalyst/SCHEMA.md.
ExitEvery route exercised with curl in the Development environment. A 20-minute audio file transcribes end to end through the job path.
25–7 days

Client: swap the data layer, keep the crypto

  • Introduce a small api object in the HTML that wraps fetch to the same-origin function, and replace the 20-odd SB.from(...), SB.storage, and SB.auth call sites with it. enc, dec, encAudioBin, decAudioBin, and the vault unlock flow do not change.
  • Entry save: encrypt as today, PUT ciphertext to Stratus via signed URL, then upsert metadata. Entry load: one metadata query, then fetch and decrypt objects, cached in IDB.
  • Transcription: submit job, poll. Keep local Whisper as the fallback exactly as it is now. Delete the transcript_status = 'pending' watchdog; a job either completes or fails with a reason.
  • Tier 3a (IDB) untouched. Tier 3b: batch-signed draft chunk uploads.
  • Rename the file to index.html so no rewrite is needed. Remove the Supabase JS CDN script.
ExitFull walkthrough on desktop and iPhone against the Development environment: sign up, create vault, record, lock screen, sync, photo, Fitbit connect, admin panel, second-device unlock.
32–3 days

Data migration script, rehearsed against dev

  • Export from Supabase with the service role key: every table to JSON, every storage object to disk, auth.users to a list of uuid → email.
  • Create the eight users in Catalyst by email. Build the uuid → catalyst_user_id map.
  • Transform: rewrite user_id everywhere, convert entries.iv/ct integer arrays into the binary object format, base64 the small ciphertext columns, rename storage paths to the new user IDs.
  • Import: table rows through the Node SDK bulk write, objects into Stratus. Idempotent, so it can be re-run.
  • Verify: for one test account, unlock on the new site with the real passphrase and confirm entry count, a transcript, an audio playback, and a photo.
ExitScript runs clean twice in a row against dev. Row and object counts match the Supabase totals.
41 day

Pre-cutover checklist

  • Ask every user to open the current app once on each device so IndexedDB recovery buffers drain. Those buffers are per-origin and will not follow them.
  • Deploy the client and functions to Catalyst Production. Set production secrets.
  • Register the new redirect URI in the Fitbit developer app. Users will reconnect Fitbit once.
  • Send invites from Catalyst so users set their login password ahead of time.
  • Put the current Vercel site into read-only mode with a banner pointing at the new address.
ExitNo pending uploads on any device. Everyone has a working Catalyst login.
51 day

Cutover

  • Run the migration script against production.
  • Unlock on the new site with your own vault. Check the admin panel totals.
  • Point the custom domain, if you use one, at Slate. Otherwise share the new Catalyst address; the installed PWA on each phone needs to be reinstalled from the new origin.
  • Keep Supabase alive, untouched, for 30 days as the rollback.
ExitEvery user has unlocked once on the new site. Errors table quiet for 48 hours.
6½ day

Decommission

  • Delete the Vercel project. Pause, then delete the Supabase project after the 30-day window.
  • Rotate the Groq, Anthropic, and Fitbit secrets so nothing from the old platform remains valid.
  • Remove supabase/ and vercel.json from the repo; update the README.

Confirm in the Catalyst console before phase 1

These are the specifics the public docs did not state. Each maps to a spike task.

Hosting
Does Slate deploy a repository with no build command, and can it serve index.html at / with correct MIME types for .webmanifest and .js workers?
Auth
Does the embedded login session carry to Advanced I/O functions on a Slate-hosted app, and does a custom domain change that? Is Custom User Validation the right place for a sign-up allow-list?
Stratus
Pre-signed PUT and GET URL support, maximum expiry, per-object size cap, bucket CORS from the app origin, and whether the account has Stratus enabled or needs an early-access request.
Jobs
Is Job Scheduling available on the account, what is its execution budget, and what does a job cost per run versus an Event function?
Billing
Free tier renews monthly; once exceeded there is a minimum charge per project. Compare against what Supabase and Vercel cost you today before committing.

What you get out of it

  • One vendor, one console, one bill. Hosting, auth, data, storage, functions, cron.
  • Transcription that cannot get stuck. The job model replaces the pending-state watchdog and the local-Whisper fallback dance.
  • No CORS allowlists and no service-role key. Functions run behind the app's own origin.
  • Encryption model unchanged. Catalyst holds ciphertext and a salt, same as Supabase did.

What you give up: direct browser-to-database calls, and 90-second synchronous functions. Both are replaced with patterns that are arguably better, at the cost of about four weeks.
